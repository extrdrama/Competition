| 项目 | 内容 |
| --- | --- |
| 作品名称 | 凭迹 CredWatch —— 云上凭据泄露自动化检测平台 |
| 参赛类别 | 揭榜挑战赛 · 题目3《云上凭据泄露的自动化检测》 |
| 作品类型 | 防御性安全研究工具（开源软件） |
| 技术栈 | Python 3.12 + SQLite（可选 PostgreSQL） + Streamlit |

---

## 一、作品概述

**一句话**：凭迹（CredWatch）是一套面向防御目的的平台，持续监测 15 类公开渠道
（代码托管平台、容器镜像仓库、软件包仓库、Paste 分享站点、Wiki 知识库、App 与小程序等），
自动发现其中暴露的云上凭据（AccessKey/SecretKey、API Token、数据库连接串、SSH 私钥、
OAuth Client Secret、支付商户密钥等），并将"凭据从公开暴露到被责任主体感知"的时间窗口
从行业常见的数天至数月，压缩到**分钟级**。

**解决的核心问题**：云上凭据一旦泄露，攻击者能以"合法身份"访问资源，绕过绝大多数
传统安全防护。而现有方案要么只能扫描单个代码仓库（覆盖不了公开渠道），
要么只报"疑似泄露"而无法确认凭据是否仍然可用、归属于谁、该如何处置。

---

## 二、主要创新点

1. **凭据对关联（组合风险分析）**：识别"单条无法利用、成对出现才构成完整凭据"的组合
   （如 AccessKey ID + Secret、OAuth Client ID + Client Secret、JWT + 签名密钥），
   将组合风险升级为最高等级——这是多数同类工具不做、但真实安全价值极高的一层。
2. **可解释概率评分 + 权重自适应**：把"命中是否为真实凭据"建模为特征向量的概率，
   每条判定都能解释"为什么"；并可从人工反馈样本中自动校准权重，实现"越用越准"。
3. **误报反馈闭环**：误报不是加白名单，而是作为训练样本重新调整判定边界，
   形成"标注 → 校准 → 生效 → 抑制 → 复核"的完整闭环。
4. **规则自动归纳**：从已确认的泄露样本自动起草候选规则（公共前缀、长度区间、字符集、
   熵区间 + 冲突检测），应对新平台格式变化。
5. **容器镜像"删了不等于没有"检测**：镜像分层存储 + 构建历史（ENV/ARG 残留）
   是容易被忽略的高危泄露渠道。

---

## 三、技术方案

**五层架构**：

```
采集层（15 渠道 / 插件化注册） → 解析层（文本抽取 + 归档/镜像层/小程序解包）
  → 检测层（四层收敛：规则/结构化/熵命中 → 占位符过滤 → 概率评分 → 只读验活）
  → 验证层（16 个只读验证器） → 输出层（指纹去重 + 凭据对关联 + 归属 + 处置建议 + MTTD）
```

**关键指标**：

| 维度 | 数据 |
| --- | --- |
| 支持公开渠道 | 15 个 / 10 类 |
| 检测规则 | 177 条 / 6 大类 / 51 种凭据类型 |
| 只读活性验证器 | 16 个（其中 13 个可发起真实只读验证；AWS SigV4 / 阿里云 / 腾讯云签名自实现） |
| 吞吐量 | 138.9 文档/秒（2000 文档基准，固定种子可复现） |
| 误报控制 | 演示语料反例（占位符/示例 DSN/私钥头）零命中 |
| 发现延迟 MTTD | 中位数 0.12 小时（离线演示） |

## 四、应用价值

1. **对个人与团队**：接入企业内网目录与 CI，把硬编码凭据挡在发布之前；
2. **对平台责任主体**：给出凭据归属、影响面、是否仍可用，以及可复制的修复代码片段，
   让应急响应从"发现即删"升级为"定位 → 吊销 → 根因修复 → 复核"；
3. **对社会**：严格遵循防御性边界（只读公开内容、只读验活、明文不落盘、
   负责任披露），符合《网络安全法》与《网络产品安全漏洞管理规定》。

---

## 五、合规与伦理（赛题硬性要求）

- 只读取**公开可访问**内容，不登录、不绕过鉴权、不越权；
- 活性验证仅调用目标平台**只读身份查询接口**，默认关闭、全局限速；
- 凭据只以**掩码 + HMAC 指纹**落盘，平台自身不成为新的泄露源；
- 发现凭据后按**负责任披露**流程通知责任主体，不进行任何利用。
- 详细声明见《合规与伦理声明》；原创性边界与开源引用见《引用与开源组件说明》。
