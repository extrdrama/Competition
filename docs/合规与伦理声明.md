# 凭迹 CredWatch · 合规与伦理声明

赛题明确要求："**本赛事只接受防御性的题目，不接受任何具有攻击性质或与
国家有关法律法规相违背的题目**"。本文档说明本平台如何在设计层面（而非
仅靠文档承诺）保证这一点。

---

## 一、行为边界

| 我们做什么 | 我们不做什么 |
| --- | --- |
| 读取**公开可访问**的网页、API、镜像与安装包 | 不登录、不注册、不绕过任何访问控制 |
| 调用平台**官方开放 API** | 不对平台发起爬虫式高频抓取 |
| 调用云厂商**只读身份查询接口**验证凭据是否有效 | 不列举、不读取、不修改、不删除任何云上资源 |
| 记录凭据的**掩码与指纹** | 不存储、不导出、不传输任何明文凭据 |
| 输出负责任披露建议 | 不利用凭据进行横向移动、数据窃取或任何后续操作 |

### 三个"绝不"

1. **绝不利用**：平台没有任何"使用凭据"的代码路径。
   验证器只能调用语义为"我是谁"的接口，框架层面不提供资源操作能力。
2. **绝不停留**：扫描结果是掩码 + 指纹 + 证据位置，明文在内存中用完即弃。
3. **绝不攻击**：平台不包含任何漏洞利用、口令爆破、越权访问代码。

## 二、活性验证的安全护栏

活性验证会向第三方发起真实请求，因此设置了**三重代码级护栏**：

### 护栏一：默认关闭

```
CREDWATCH_ENABLE_VALIDATION=false   # 默认值
```

不显式开启时，`make_validator()` 直接返回 `None`，
检测流水线跳过整个验证环节——**连验证模块的导入都不会发生**（延迟导入），
因此不存在"误触发"的可能。

### 护栏二：全局限速

```python
class ValidationGuard:
    def allow(self) -> bool:
        if not self.enabled:
            return False
        with self._lock:
            # 滑动窗口，默认 20 次/分钟
```

即使开启验证，也不会对第三方平台造成压力。达到上限后自动跳过后续验证，
并在日志中给出明确警告。

### 护栏三：只读接口白名单

验证器注册表（`credwatch/validators/base.py`）是**封闭**的。
每个验证器都必须在注释中说明所用端点，且端点语义必须是
"读取自身身份/权限"：

| 验证器 | 端点性质 |
| --- | --- |
| `aws` / `aliyun` / `tencent` | `GetCallerIdentity`——查询"我是谁"，无任何资源访问 |
| `github` / `gitlab` / `gitee` | `GET /user`——读取令牌归属账号 |
| `slack` | `auth.test`——校验令牌有效性 |
| `openai` / `anthropic` | `GET /v1/models`——只读列出模型，不产生费用 |
| `stripe` | `GET /v1/balance`——只读查询余额，不产生交易 |
| `sendgrid` | `GET /v3/scopes`——只读查询权限范围 |

**主动拒绝**：凡是需要发送消息、创建资源、产生费用的接口，
一律不实现。例如邮件服务的"发送测试邮件"接口、支付平台的"创建订单"接口。

**诚实标注无法验证的**：华为云 STS 接口需按区域端点签名，且缺少统一的
匿名验证入口；Google API Key 的可用性取决于启用了哪些服务。
两者都**不发起任何请求**，直接返回"无法判定，建议人工复核"——
不做猜测性判定，避免把"未启用某服务"误报为"凭据无效"。

## 三、数据安全

平台自身必须避免成为新的泄露源。

| 措施 | 实现位置 |
| --- | --- |
| 明文不落盘 | `Finding.to_record()` 主动丢弃 `raw` 字段 |
| 掩码固定长度 | `mask_secret()` 中间固定 4 星号，不泄露真实长度 |
| 私钥不保留内容 | 只保留 `-----BEGIN ... -----` 头部与字节数 |
| 指纹带盐 HMAC | `fingerprint()` 使用 `CREDWATCH_HMAC_SALT` |
| 命中片段脱敏 | `snippet_of()` 把片段中的明文替换为掩码 |
| 报告脱敏 | 单元测试 `test_no_plaintext_in_json_output` 断言全库无明文 |

**盐值管理提示**：`CREDWATCH_HMAC_SALT` 一旦更换，历史指纹将无法与新增
指纹比对，请妥善保管并做好备份。

## 四、对第三方平台的态度

我们认可并主动遵守各平台的服务条款：

- **GitHub**：使用官方 API 与清晰的自定义 User-Agent；
  通过 `TokenPool` 轮换令牌并配合指数退避，避免打满速率限制；
  优先使用公开的 `raw.githubusercontent.com` 而非 API 配额。
- **Docker Hub**：仅拉取公开镜像，使用匿名令牌；对超大层主动跳过。
- **npm / PyPI**：仅下载公开包，控制单包体积上限；使用官方"最近更新"榜单
  而非全量遍历。
- **Wiki / Paste 站点**：仅访问公开列表与公开 Raw 页；单条内容超过 1 MB 即跳过。
- **微博**：仅使用开放平台官方 API。未配置访问令牌时**直接跳过该渠道**，
  不会退化为主力爬虫。

## 五、负责任披露

发现凭据泄露后，正确的做法是通知责任主体，而不是利用它。平台在报告中
为每条发现给出针对性的披露建议：

| 渠道 | 建议披露路径 |
| --- | --- |
| GitHub | 仓库 Security 页面 / GitHub 官方私密漏洞报告渠道 |
| Gitee | 仓库负责人主页联系方式 |
| GitLab | 项目维护者联系方式或实例管理员 |
| 容器镜像 | 镜像仓库维护者或平台投诉通道 |
| npm | `package.json` 中的 maintainers 邮箱 |
| PyPI | 项目维护者邮箱 |
| Paste 站点 | 联系平台方删除内容（通常无法联系作者） |
| Wiki | 站点管理员或页面历史中的作者 |
| 微博 | 博主私信或平台举报通道 |
| App | 应用市场开发者联系方式或工信部备案主体 |
| 小程序 | 微信开放平台主体 |
| 云厂商凭据 | 同步通知对应云厂商应急响应中心 |

本平台的设计与使用遵循：

- 《中华人民共和国网络安全法》

- 《中华人民共和国个人信息保护法》

**使用约束**：本平台仅可用于授权的安全研究、自有资产自查与学术竞赛。
使用者须确保对检测目标拥有合法授权。**禁止**将其用于任何未授权的检测、
侦察或渗透活动。

发现凭据泄露时，应通过负责任的披露流程通知责任主体，
**不得**进行任何形式的利用、传播或牟利。
