## 四、诚实评估：三个真实风险项

### 风险 1（已缓解）：真实渠道扫描实绩

**已完成**：在无需令牌的前提下，用 GitHub 公开 Gist（`/gists/public` 公开接口）
完成了三轮独立实测（120 / 1103 / 1200 份文档 → 57 / 199 / 165 条唯一凭据，
critical 最高 46，含真实泄露的 OpenSSH 私钥与数字资产私钥），最快发现
为公开后 2.4 分钟，并据真实数据修复了 2 个精度缺陷。
详见《测试报告》第八节，复现命令：`python scripts/demo_real_scan.py`。

**进一步建议**：配置 GitHub PAT 后可开启代码搜索模式，扩大覆盖面；
若能增加镜像仓库 / 包仓库的真实样本，实绩会更完整。

### 风险 2：题目 3 原文未逐字核对

《赛题指南》网页只完整渲染了题目 1。**必须下载官网附件 1**，
逐字核对题目 3 的要求（尤其是"交付件"清单和"评价方式"的权重项），
若有本表未覆盖的要求（例如要求提交特定格式的渠道清单/凭据类型清单、
或要求现场提供靶场数据），需在提交前补齐。

### 风险 3：文档 PDF 合并

官方要求**一份 PDF 文档（≤10M）**。当前 docs/ 下有 12 个 Markdown，
需要合并导出为单个 PDF，并控制体积（目前总量约 100KB，无压力）。

建议合并顺序（即官方要求的五要素）：
`作品简介 → 技术说明书（设计方案）→ 测试报告 → 支持的公开渠道列表
→ 支持的凭据类型列表 → 创新点说明 → 对比优势与基准 → 引用与开源组件说明
→ 合规与伦理声明 → 参赛作品声明`
