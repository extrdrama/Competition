# 凭迹 CredWatch · 引用与开源组件说明

本文档说明本作品的原创性边界：**哪些是本队伍自己写的，哪些使用了开源
组件，哪些只是参考了设计思路。**

之所以单独出具这份文档，是因为揭榜挑战赛明确要求
"参赛作品应是参赛队伍独立设计、开发完成的原创性作品，严禁抄袭、剽窃"。
我们把边界写清楚，而不是含糊处理。

---

## 一、原创性声明

### 1.1 完全自研的部分

以下模块为**本队伍独立设计并实现**，未复制任何第三方源码：

| 模块 | 文件 | 说明 |
| --- | --- | --- |
| 五层架构与四层收敛流水线 | `credwatch/detectors/pipeline.py` | 含位置重叠合并、按检测器分档阈值、置信度合成算法 |
| 规则引擎 | `credwatch/detectors/rule_engine.py` | YAML 规则加载、`secret_group`、`require_keywords` 邻域校验、两级占位符过滤 |
| 结构化解析 | `credwatch/detectors/structured.py` | dotenv / INI / k8s Secret（Base64 解码）/ 镜像构建历史 / PEM 整块提取 |
| 熵检测 | `credwatch/detectors/entropy.py` | 香农熵 + 字符集约束 + 噪声过滤 |
| 上下文评分 | `credwatch/detectors/context.py` | 九项加权证据、正负向打分、按检测器分档阈值 |
| 检测规则库（195 条） | `config/rules/*.yaml` | **全部自行编写**，见第二节说明 |
| 渠道适配器（15 个） | `credwatch/sources/*.py` | 含限速器、令牌池、游标增量、归档展开 |
| 归档解包器 | `credwatch/parsers/archive.py` | 含 **wxapkg 格式自行实现**的解析器、zip bomb 防护 |
| 只读活性验证器（16 个） | `credwatch/validators/*.py` | 含 **AWS SigV4 / 阿里云 HMAC-SHA1 / 腾讯云 TC3 签名自行实现** |
| 指纹去重与跨渠道关联 | `credwatch/dedup.py` | 带盐 HMAC 指纹、风险升级、置信度调整 |
| 归属识别 | `credwatch/attribution.py` | 主体抽取、组织类型推断、披露路径映射 |
| 存储层 | `credwatch/storage.py` | SQLite 模式、明文丢弃、增量游标 |
| 扫描引擎与调度 | `credwatch/scheduler.py` | 单渠道故障隔离、统计聚合 |
| 报告与看板 | `credwatch/report.py` `dashboard.py` | MTTD 度量、收敛漏斗、脱敏渲染 |
| 演示语料生成器 | `scripts/make_demo_samples.py` | 固定随机种子，结果可复现 |

### 1.2 关键算法的实现说明

**签名算法**：AWS SigV4、阿里云 HMAC-SHA1、腾讯云 TC3-HMAC-SHA256
均依据各云厂商**公开的接口签名文档**自行实现，未使用任何云 SDK。

**wxapkg 解包**：依据微信小程序包的公开文件格式说明自行实现
（14 字节头部 + 索引区 + 数据区），代码中附有格式注释。

**没有使用任何现成的凭据扫描引擎**。下表中的项目仅作为设计参考。

## 二、规则库的原创性说明

检测规则库（195 条）**全部由本队伍自行编写**。规则格式依据的是
各平台**官方文档中公开的凭据格式说明**：

| 规则类别 | 格式依据 |
| --- | --- |
| 云厂商 AKSK 前缀与长度 | AWS / 阿里云 / 腾讯云 / 华为云官方文档 |
| 平台令牌格式（`ghp_` / `glpat-` / `npm_` / `dckr_pat_` 等） | 各平台官方文档与开发者指南 |
| 连接串格式 | 各数据库官方连接字符串规范 |
| 私钥文件格式 | RFC 7468（PEM）、OpenSSH 密钥格式规范 |
| Webhook 地址格式 | 各协作平台开放平台文档 |

**明确声明**：未复制、未移植、未改写任何第三方项目的规则文件
（包括但不限于 gitleaks 的 `gitleaks.toml`、trufflehog 的 detectors、
noseyparker 的规则集、detect-secrets 的 plugins）。

规则的组织方式、字段设计（`secret_group`、`require_keywords`、
`multiline`、`entropy`）以及配套的上下文评分机制均为本作品自行设计。

## 四、直接依赖的开源组件

本作品**运行时依赖**仅三个通用库，均为宽许可（MIT / Apache-2.0），
且都是通用网络与配置处理库，不含任何安全检测逻辑：

| 组件 | 版本要求 | 许可证 | 用途 | 替代方案 |
| --- | --- | --- | --- | --- |
| [requests](https://github.com/psf/requests) | ≥2.31.0 | Apache-2.0 | HTTP 客户端 | 标准库 `urllib.request` |
| [PyYAML](https://github.com/yaml/pyyaml) | ≥6.0.1 | MIT | 规则与配置文件解析 | 标准库 `json`（需改格式） |
| [rich](https://github.com/Textualize/rich) | ≥13.7.0 | MIT | 终端表格渲染（**可选**，缺失时自动降级为纯文本） | — |

其他能力均使用 **Python 标准库**实现，包括：

| 能力 | 标准库 |
| --- | --- |
| 数据库 | `sqlite3` |
| 归档解包 | `zipfile` / `tarfile` / `gzip` |
| 加密签名 | `hmac` / `hashlib` / `base64` |
| 正则与文本处理 | `re` / `string` |
| 目录遍历 | `os` / `pathlib` / `fnmatch` |
| 并发与时间 | `threading` / `time` / `datetime` |

**可选依赖**（不安装不影响核心功能）：
- `streamlit`（≥1.31.0，Apache-2.0）：可视化看板；
- `psycopg2-binary`：PostgreSQL 存储（默认使用 SQLite，无需该依赖）；
- `jadx`（外部命令行工具）：APK 反编译增强，未安装时自动降级为 dex 字符串抽取。

## 五、演示数据说明

本作品**不附带任何演示凭据文件**。`demo` 命令默认执行实时真实扫描
（GitHub 公开 Gist，公开接口、只读），结果仅以掩码与 HMAC 指纹呈现，
不存储、不展示任何明文凭据；对外主张的全部数据均来自真实实测
（见《测试报告》第八节）。

单元测试中的凭据样本为**程序生成的伪造值**（内联于测试代码，
固定可复现），不对应任何真实账号。

因此本仓库可以安全地公开分发，不存在因示例数据导致的泄露风险。
